# 面试题编写

两回合流程：**出题回合只给题目** → 用户作答 → **判卷回合给对错与原因，并更新错题集**。永远不要在出题回合泄露答案。

## 边界（先看）

- **只读笔记正文**：不改动 `20-areas/` 下的笔记文件。
- **有据可依**：每题都能指回出处；笔记没讲的点不出，或显式标注 `扩展题（超出笔记范围）`。
- **写文件的范围**：本轮新增题库、答案、错题集文件属于流程默认动作；改动其他既有笔记、或在 MOC 里加索引入口，仍要先给方案等用户确认。
- **分工**：文件结构与链接卫生归 `obsidian-organizer`；本 skill 只负责出题、判卷与错题集。

## 一、定位素材

主题来源按优先级判定：

1. 用户点名的笔记或目录；
2. 错题重练：用户说“复习错题”“练错题”时，直接以 `40-reviews/错题集.md` 为素材来源；
3. 知识地图（MOC）：`20-areas/django/2026-09-18-Django知识地图.md`、`20-areas/ai/2026-10-11-AI知识地图.md`；
4. 话题标签：如 `orm`、`中间件`、`langchain`、`安全`；
5. 用户只给范围词（“复习 Django”）时，用 MOC 的章节分组界定范围，并说明取了哪几组。

笔记库规模：`20-areas/` 共 44 篇（python 4、django 15、django/orm 13、ai 10、database 1），每篇都带 `tags` 与 `description`，可作为主题索引。

读取顺序（控制上下文）：frontmatter → 各级标题 → 只读命中的小节正文。用 `grep` 定位小节，用 `read` 的 `offset`/`limit` 局部读取，不要通读全库。

## 二、出题纪律（硬约束）

1. 每道题都能写成 `[[笔记名#小节标题]]` 形式的出处，锚点与目标笔记标题逐字一致。
2. 只考笔记里写过的内容，不改写笔记的观点、数值、代码与结论。
3. 笔记未覆盖但面试常考的延伸点：要么不出，要么标 `扩展题（超出笔记范围）`，并在解析里说明笔记只讲到哪一步。
4. 干扰项优先取自笔记里的真实误区，例如反例代码、“如果没有 X 会怎样”的对比、“常见坑”小节；不要凭空编造错误说法，也不要留下明显不成立的凑数选项。
5. 题间去重；同一考点最多一道题，除非用户要求多角度追问。
6. 覆盖所选范围里的各大节，不要只挑某一节反复出题。

## 三、难度与题型

| 等级 | 考查目标 | 典型问法 |
|---|---|---|
| L1 记忆 | 术语、取值、命令、签名 | 定义是什么、有哪些取值 |
| L2 理解 | 机制与因果 | 为什么这样设计、两者区别 |
| L3 应用 | 写得出、用得对 | 写代码、给场景选方案 |
| L4 排错/场景 | 定位与权衡 | 这段代码错在哪、线上怎么优化 |

题型：单选、多选、判断改错、简答、代码题、场景/设计题。

用户未指定配比时的默认分布：L1 20%、L2 30%、L3 30%、L4 20%。

## 四、默认参数（用户未指定时采用，并在回复开头一句话声明）

- 题量：10 道；
- **答案：默认不给**，只写入答案文件，等用户作答后再在判卷回合给出；
- 范围：以用户指定的主题为准；完全没给主题时问一句，不要自行缩到单篇笔记；
- 落盘：默认落盘题目卷与答案文件。

## 五、出题回合（硬规则）

1. **回复里只有题目**：不出现答案、解析、正确选项暗示（如“注意”“关键在”“这题选…”），也不给排除提示。
2. **题目卷文件里不写答案**，包括 HTML 注释、折叠块、frontmatter 字段。
3. 题目顺序与文件中的题号一一对应，判卷时按题号对齐。
4. 回复末尾只用一句话说明作答方式（把答案发回来判卷），不复述题干之外的提示。
5. 题目格式（题号作为标题，保证锚点稳定）：

   ```markdown
   ### 第 1 题

   *L1 记忆 · 单选*

   题干文字

   A. 选项一
   B. 选项二
   ```

   多选题在题头标 `多选`，并注明“少选、多选均不得分”；代码题把代码放进带语言标注的代码块。

6. 题目若来自错题重练，不标注哪几道是错题，只在题目卷开头注明“含 N 道错题重练”。

## 六、落盘（出题回合）

| 文件 | 内容 |
|---|---|
| `40-reviews/YYYY-MM-DD-<主题>面试题.md` | 只有题目与 frontmatter |
| `40-reviews/.answers/YYYY-MM-DD-<主题>答案.md` | 答案、解析、出处 |

- frontmatter 沿用仓库规范：`tags` 写主题技术 + `面试题`，`description` 一句话说明覆盖范围与题量。
- 题目卷正文：H1 + 每题 `### 第 N 题`。
- 答案文件：每题 `**第 N 题 · 答案 X**` + 解析（为什么对、其余选项错在哪）+ 出处。
- `40-reviews/` 或 `.answers/` 不存在则创建；同名文件已存在时加 `-2` 序号后缀，不覆盖已有文件。
- 答案文件放在 `.answers/` 子目录：Obsidian 默认不显示点目录，避免顺手翻到答案。

## 七、判卷回合

用户把答案发来后：

1. 读取对应的题目卷、`40-reviews/.answers/` 里的答案文件、`40-reviews/错题集.md`。
2. 逐题给出：用户答案 / 正确答案 / 对错 / 原因（对在哪、错在哪，引用笔记结论）/ 出处。
3. 只判对错，不夹带超纲拓展；用户答案含义不清时先问一句再判，不要替他解释成正确的。
4. 汇总：正确率 + 错题清单（按题号）。
5. 更新错题集（见第八节），并报告每道错题的连对进度与本次移除的条目。
6. 判卷结果落盘：把逐题结论追加到答案文件末尾的 `## 判卷记录` 小节，保留每次作答时间。

## 八、错题集与重练规则（`40-reviews/错题集.md`）

### 条目格式

```markdown
### PY-001 · 单选 · 考点：隐式类型转换

- 主题：python基础知识
- 来源：[[2026-10-15-Python基础知识面试题#第 1 题]]
- 出处：[[2026-09-10-Python基础知识#数值类型]]
- 连对次数：0/3
- 最近作答：2026-10-15 · 答错
- 错因：忽略 True 可以当 1 参与运算
- 题干：下列表达式中，结果为整数 2 的是……
- 正确答案：A
- 我的答案：C
```

- **ID**：`<主题缩写>-<三位序号>`，缩写如 `PY`（python）、`ORM`、`DJ`（django）、`AI`、`DB`，序号按现有最大值递增，不复用。
- 条目放在 `## 待复习` 小节下；重练过的条目更新 `连对次数` 与 `最近作答`，不新建重复条目（按考点去重）。

### 计数规则

- 答对 → `连对次数 +1`；
- 答错 → `连对次数` 重置为 `0`，更新 `错因` 与 `最近作答`；
- **达到 `3/3` 立即从错题集删除该条目**，并在回复里说明“已移出错题集”；
- 必须是连续答对：期间任何一次答错即清零重新计数。

### 入集规则

- 任何答错的题都必须在错题集里：新题答错就新增条目（起始 `0/3`），错题重练再错则重置已有条目。

### 重练规则（出题前执行）

1. 先读 `40-reviews/错题集.md`，筛出与本次主题相同、或考点相同的条目；
2. 存在匹配错题时，错题占本次题量的 **50%**（向下取整，至少 1 道），其余为新题；可用错题不足 50% 时，全部用上；
3. 错题优先级：连对次数少者优先，其次最近答错者优先；
4. 同一道错题在同一份卷子里只出现一次，可以换问法、打乱选项顺序，但考点与答案不能变；
5. 没有匹配错题时，全部出新题；
6. 重练题同样要有出处与解析，答案照旧写进答案文件。

## 九、交付前自检

出题回合：

- [ ] 回复中没有答案、解析或正确选项暗示；
- [ ] 题目卷文件里没有答案，也没有形如 `<!-- -->` 的答案残留；
- [ ] 答案文件已写入，且每题出处锚点在目标笔记里逐字存在；
- [ ] 没有重复题，难度分布与声明一致；
- [ ] 已按重练规则纳入错题（若错题集有匹配条目）。

判卷回合：

- [ ] 逐题给了对错与原因，且引用笔记结论而不是自己发挥；
- [ ] 错题集已更新：答对 +1、答错清零、满 3 次已移除；
- [ ] 判卷记录已追加到答案文件；
- [ ] 未改动 `20-areas/` 下的任何笔记。
