# Django关联模型与范式

## Django 关联模型与查询优化完全指南

### 一、范式理论（数据库设计基础）

在讲 Django 关联之前，先理解数据库范式。它决定了"数据该怎么拆表"。

#### 1. 第一范式（1NF）：字段原子性

**每个字段不可再分**。

```
❌ 反例：
student 表
| id | name | phones              |
| 1  | 张三 | 138xxx,139xxx,137xx |

✅ 正例：
student 表
| id | name |
| 1  | 张三 |

phone 表
| id | student_id | phone   |
| 1  | 1          | 138xxx  |
| 2  | 1          | 139xxx  |
```

一个字段存多个值，违反 1NF。

#### 2. 第二范式（2NF）：消除部分依赖

**非主键字段必须完全依赖主键**，不能只依赖主键的一部分（针对联合主键）。

```
❌ 反例：联合主键 (student_id, course_id)
| student_id | course_id | student_name | course_name | score |
| 1          | 101       | 张三         | 数学        | 90    |

student_name 只依赖 student_id，不依赖 course_id → 违反 2NF

✅ 拆成三张表：
student(id, name)
course(id, name)
enrollment(student_id, course_id, score)
```

#### 3. 第三范式（3NF）：消除传递依赖

**非主键字段不能依赖其他非主键字段**。

```
❌ 反例：
student 表
| id | name | class_id | class_name |
| 1  | 张三 | 5        | 3年级5班   |

class_name 依赖 class_id，class_id 依赖 id → 传递依赖 → 违反 3NF

✅ 拆成两张表：
class(id, name)
student(id, name, class_id)
```

#### 4. 范式与反范式

| 范式 | 优点 | 缺点 |
|---|---|---|
| 遵循范式 | 无冗余、易维护、数据一致 | 查询要 JOIN，性能差 |
| 反范式 | 查询快、少 JOIN | 数据冗余、更新麻烦 |

**实际项目**：核心数据遵循 3NF，报表、统计场景适度反范式（加冗余字段）。

#### 5. Django 中的体现

| 关系 | 数据库实现 | Django 字段 |
|---|---|---|
| 一对一 | 外键 + UNIQUE | `OneToOneField` |
| 一对多 | 外键 | `ForeignKey` |
| 多对多 | 中间表 | `ManyToManyField` |
| 自关联 | 外键指向自身 | `ForeignKey("self")` |

### 二、一对一关联（OneToOneField）

#### 1. 场景

一个学生对应一个学籍档案，一个用户对应一个个人资料。

#### 2. 模型定义

```python
from django.db import models


class Student(models.Model):
    name = models.CharField(max_length=100)


class Profile(models.Model):
    student = models.OneToOneField(
        Student,
        on_delete=models.CASCADE,
        related_name="profile",
    )
    bio = models.TextField()
    id_card = models.CharField(max_length=18, unique=True)
```

**生成的表**：

```sql
CREATE TABLE profile (
    id INTEGER PRIMARY KEY,
    student_id INTEGER UNIQUE REFERENCES student(id),
    bio TEXT,
    id_card VARCHAR(18) UNIQUE
);
```

**关键**：`OneToOneField` 在数据库层是**外键 + UNIQUE 约束**。

#### 3. 查询

```python
# 正向：学生 → 档案
student = Student.objects.get(pk=1)
profile = student.profile          # 自动关联
profile = student.profile.bio

# 反向：档案 → 学生
profile = Profile.objects.get(pk=1)
student = profile.student

# 查询时预加载
student = Student.objects.select_related("profile").get(pk=1)
```

#### 4. 不存在时的处理

```python
# 如果 profile 不存在，student.profile 会抛 Profile.DoesNotExist
try:
    profile = student.profile
except Profile.DoesNotExist:
    profile = None

# 或用 hasattr
if hasattr(student, "profile"):
    ...
```

#### 5. 适用场景

| 场景        | 是否适合 |
| --------- | ---- |
| 用户 + 个人资料 | ✅    |
| 学生 + 学籍档案 | ✅    |
| 订单 + 发票   | ✅    |
| 可选扩展信息    | ✅    |
| 频繁一起查询    | ✅    |

**核心理由**：把不常用、可能为空的字段拆到单独的"扩展表"，避免主表过宽。

### 三、一对多关联（ForeignKey）

#### 1. 场景

一个班级有多个学生，一个作者有多篇文章。

#### 2. 模型定义

```python
class Class(models.Model):
    name = models.CharField(max_length=50)


class Student(models.Model):
    name = models.CharField(max_length=100)
    class_obj = models.ForeignKey(
        Class,
        on_delete=models.CASCADE,
        related_name="students",
        db_index=True,
    )
```

**生成的表**：

```sql
CREATE TABLE student (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100),
    class_obj_id INTEGER REFERENCES class(id)
);
CREATE INDEX student_class_obj_id_idx ON student(class_obj_id);
```

**关键**：`ForeignKey` 字段在数据库里是 `字段名_id`，Django 自动加索引。

#### 3. `on_delete` 的 7 种取值

| 取值 | 行为 | 适用场景 |
|---|---|---|
| `CASCADE` | 级联删除 | 子记录依赖父记录 |
| `PROTECT` | 阻止删除 | 父记录不能随便删 |
| `RESTRICT` | 类似 PROTECT，更严格 | Django 3.1+ |
| `SET_NULL` | 外键置 NULL | 需要 `null=True` |
| `SET_DEFAULT` | 外键置默认值 | 需要 `default` |
| `SET(value)` | 外键置指定值 | 自定义 |
| `DO_NOTHING` | 什么都不做 | 不推荐 |

```python
# 班级删了，学生也删
class_obj = models.ForeignKey(Class, on_delete=models.CASCADE)

# 班级有学生时不能删
class_obj = models.ForeignKey(Class, on_delete=models.PROTECT)

# 班级删了，学生的 class_obj 置空
class_obj = models.ForeignKey(Class, on_delete=models.SET_NULL, null=True)
```


#### 4. 查询

```python
# 正向：学生 → 班级
student = Student.objects.get(pk=1)
class_obj = student.class_obj
class_name = student.class_obj.name

# 反向：班级 → 所有学生
class_obj = Class.objects.get(pk=1)
students = class_obj.students.all()   # related_name
```

#### 5. 反向查询的 `related_name`

```python
# 不写 related_name：默认是 模型名小写_set
class_obj.student_set.all()

# 写了 related_name="students"
class_obj.students.all()
```

**推荐始终写 `related_name`**，语义清晰。

#### 6. 跨表查询

```python
# 查"3年级5班"的所有学生
Student.objects.filter(class_obj__name="3年级5班")

# 查有学生的班级
Class.objects.filter(students__isnull=False).distinct()

# 查学生数大于 10 的班级
from django.db.models import Count
Class.objects.annotate(count=Count("students")).filter(count__gt=10)
```


#### 7. 性能：`select_related`

```python
# ❌ N+1 问题：查 100 个学生，每个都查一次班级
students = Student.objects.all()
for s in students:
    print(s.class_obj.name)   # 100 次查询

# ✅ 一次 JOIN 搞定
students = Student.objects.select_related("class_obj").all()
for s in students:
    print(s.class_obj.name)   # 1 次查询
```

### 四、多对多关联（ManyToManyField）

#### 1. 场景

一篇文章有多个标签，一个标签属于多篇文章。

#### 2. 模型定义

```python
class Article(models.Model):
    title = models.CharField(max_length=200)
    tags = models.ManyToManyField(
        "Tag",
        related_name="articles",
        blank=True,
    )


class Tag(models.Model):
    name = models.CharField(max_length=50, unique=True)
```

**生成的表**：

```sql
CREATE TABLE article (id INTEGER PRIMARY KEY, title VARCHAR(200));
CREATE TABLE tag (id INTEGER PRIMARY KEY, name VARCHAR(50) UNIQUE);

-- 中间表（Django 自动创建）
CREATE TABLE article_tags (
    id INTEGER PRIMARY KEY,
    article_id INTEGER REFERENCES article(id),
    tag_id INTEGER REFERENCES tag(id),
    UNIQUE (article_id, tag_id)
);
```

#### 3. 自定义中间表

如果中间表需要额外字段（比如"关注时间"、"权重"），用 `through`：

```python
class Article(models.Model):
    title = models.CharField(max_length=200)
    tags = models.ManyToManyField("Tag", through="ArticleTag")


class Tag(models.Model):
    name = models.CharField(max_length=50)


class ArticleTag(models.Model):
    article = models.ForeignKey(Article, on_delete=models.CASCADE)
    tag = models.ForeignKey(Tag, on_delete=models.CASCADE)
    weight = models.IntegerField(default=1)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        unique_together = [["article", "tag"]]
```

**注意**：用 `through` 后，不能用 `article.tags.add(tag)`，要手动创建 `ArticleTag`。

#### 4. 查询

```python
# 正向：文章 → 标签
article = Article.objects.get(pk=1)
tags = article.tags.all()

# 反向：标签 → 文章
tag = Tag.objects.get(pk=1)
articles = tag.articles.all()

# 添加关系
article.tags.add(tag1, tag2)
article.tags.remove(tag1)
article.tags.clear()
article.tags.set([tag1, tag2])

# 跨表查询
Article.objects.filter(tags__name="python")
Tag.objects.filter(articles__title__icontains="django")
```

#### 5. 多对多的性能

```python
# ❌ N+1：每篇文章都查一次标签
articles = Article.objects.all()
for a in articles:
    print(a.tags.all())   # 每篇一次查询

# ✅ 预加载
articles = Article.objects.prefetch_related("tags").all()
for a in articles:
    print(a.tags.all())   # 2 次查询搞定
```

**多对多只能用 `prefetch_related`，不能用 `select_related`**（因为是多条记录，JOIN 会笛卡尔积）。

#### 6. 去重

跨多对多查询可能产生重复：

```python
# ❌ 一篇文章有 3 个匹配的标签，返回 3 次
Article.objects.filter(tags__name__icontains="py")

# ✅ 去重
Article.objects.filter(tags__name__icontains="py").distinct()
```

#### 7. 多对多的典型场景

| 场景 | 说明 |
|---|---|
| 文章 ↔ 标签 | 多对多 |
| 用户 ↔ 角色 | 多对多 |
| 学生 ↔ 课程 | 多对多（带成绩用中间表） |
| 商品 ↔ 分类 | 多对多 |
| 用户 ↔ 关注 | 自关联多对多 |

### 五、自关联

#### 1. 一对多自关联：树形结构

```python
class Category(models.Model):
    name = models.CharField(max_length=50)
    parent = models.ForeignKey(
        "self",
        on_delete=models.CASCADE,
        null=True,
        blank=True,
        related_name="children",
    )
```

**用法**：

```python
# 顶级分类
root = Category.objects.filter(parent__isnull=True)

# 子分类
children = root.children.all()

# 递归查所有后代
def get_descendants(category):
    result = [category]
    for child in category.children.all():
        result.extend(get_descendants(child))
    return result
```

#### 2. 多对多自关联：社交关注

```python
class User(models.Model):
    name = models.CharField(max_length=50)
    following = models.ManyToManyField(
        "self",
        symmetrical=False,   # 不对称：A 关注 B，B 不一定关注 A
        related_name="followers",
        blank=True,
    )
```

**用法**：

```python
# 我关注的人
user.following.all()

# 关注我的人
user.followers.all()

# 关注
user.following.add(other_user)

# 取消关注
user.following.remove(other_user)
```

**`symmetrical` 参数**：

| 值 | 行为 | 场景 |
|---|---|---|
| `True`（默认） | 对称，A 关联 B 则 B 也关联 A | 好友关系 |
| `False` | 不对称，A 关注 B 不等于 B 关注 A | 关注/粉丝 |

#### 3. 自关联的坑

- **`related_name` 必须写**，否则 `_set` 会冲突
- **递归查询要小心无限循环**
- **树形结构**考虑用 `django-mptt` 或 `django-treebeard`，性能更好
