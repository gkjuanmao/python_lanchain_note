# Django查询优化

## Django 关联模型与查询优化完全指南

### 七、查询优化（N+1 问题）

#### 1. 什么是 N+1

```python
# 查 100 篇文章
articles = Article.objects.all()

for a in articles:
    print(a.author.name)   # 每篇都查一次作者 → 100 次查询
```

总查询数 = 1（查文章）+ 100（查作者）= 101 次，即 **N+1**。

#### 2. `select_related` —— 一对一、一对多

**原理**：用 SQL `JOIN` 一次查出关联数据。

```python
articles = Article.objects.select_related("author", "category").all()
```

**生成的 SQL**：

```sql
SELECT article.*, author.*, category.*
FROM article
LEFT JOIN author ON article.author_id = author.id
LEFT JOIN category ON article.category_id = category.id;
```

**适用**：`ForeignKey`、`OneToOneField`（"一"端）。

#### 3. `prefetch_related` —— 多对多、一对多反向

**原理**：分两次查询，Python 层做匹配。

```python
articles = Article.objects.prefetch_related("tags").all()
```

**生成的 SQL**：

```sql
-- 第 1 次
SELECT * FROM article;

-- 第 2 次
SELECT * FROM tag
INNER JOIN article_tags ON tag.id = article_tags.tag_id
WHERE article_tags.article_id IN (1, 2, 3, ...);
```

**适用**：`ManyToManyField`、反向 `ForeignKey`。

#### 4. `select_related` vs `prefetch_related`

| 维度 | `select_related` | `prefetch_related` |
|---|---|---|
| SQL 次数 | 1 次 JOIN | 2 次查询 |
| 适用关系 | 一对一、多对一 | 多对多、一对多反向 |
| 内存 | 笛卡尔积可能大 | 分开加载，内存可控 |
| 支持过滤 | ✅ `Prefetch` | ✅ `Prefetch` |
| 支持切片 | ❌ | ✅ `Prefetch` |

#### 5. `Prefetch` 高级用法

```python
from django.db.models import Prefetch

# 只预加载已发布的文章
authors = Author.objects.prefetch_related(
    Prefetch(
        "articles",
        queryset=Article.objects.filter(is_published=True).order_by("-created_at"),
        to_attr="published_articles",   # 结果存到 author.published_articles
    )
)

for a in authors:
    for article in a.published_articles:   # 不再查库
        print(article.title)
```

**`to_attr` 的好处**：结果存到自定义属性，不污染 `a.articles.all()`。

#### 6. `only()` / `defer()` —— 只取需要的字段

```python
# 只取 id、name，其他字段延迟加载
students = Student.objects.only("id", "name")

# 排除大字段
students = Student.objects.defer("description", "avatar")
```

**注意**：访问未加载的字段会**再查一次库**，用不好反而更慢。

#### 7. `values()` / `values_list()` —— 不构造模型实例

```python
# 返回字典，不构造 Student 对象
Student.objects.values("id", "name")

# 返回元组
Student.objects.values_list("id", "name")

# 只取单个字段的列表
Student.objects.values_list("name", flat=True)
```

**性能**：比构造模型实例快，适合只读数据。

#### 8. `exists()` 替代 `bool(qs)`

```python
# ❌ 会查全部并缓存
if Student.objects.filter(status=1):
    ...

# ✅ 只查是否存在
if Student.objects.filter(status=1).exists():
    ...
```

#### 9. `count()` 替代 `len(qs)`

```python
# ❌ 加载全部到内存再计数
len(Student.objects.all())

# ✅ 数据库 COUNT(*)
Student.objects.count()
```

#### 10. `iterator()` 遍历大数据量

```python
# ❌ 一次加载 100 万条到内存
for s in Student.objects.all():
    process(s)

# ✅ 分批加载，内存友好
for s in Student.objects.iterator(chunk_size=2000):
    process(s)
```

**注意**：`iterator()` 不缓存，不能重复遍历。

#### 11. `bulk_create` / `bulk_update` / `update`

```python
# ❌ 逐条插入
for i in range(1000):
    Student.objects.create(name=f"学生{i}")

# ✅ 批量插入
Student.objects.bulk_create([Student(name=f"学生{i}") for i in range(1000)])

# ❌ 逐条更新
for s in students:
    s.status = 1
    s.save()

# ✅ 批量更新（同一个值）
Student.objects.filter(status=0).update(status=1)

# ✅ 批量更新（不同值）
Student.objects.bulk_update(students, ["status"])
```

#### 12. `select_related` 的嵌套

```python
# 多层 JOIN
Article.objects.select_related(
    "author__profile",      # 作者 → 作者资料
    "category__parent",     # 分类 → 父分类
)
```

#### 13. 索引优化

```python
class Student(models.Model):
    name = models.CharField(max_length=100, db_index=True)
    status = models.IntegerField(db_index=True)

    class Meta:
        indexes = [
            models.Index(fields=["status", "-creat_time"]),   # 联合索引
            models.Index(fields=["classmate", "sex"]),
        ]
```

**原则**：

- 经常 `filter()` 的字段加索引
- 经常 `order_by()` 的字段加索引
- 联合索引的顺序要和查询一致
- 索引不是越多越好，写入会变慢

#### 14. 避免在 `filter` 里用函数

```python
# ❌ 索引失效
Student.objects.filter(name__lower="tom")

# ✅ 用函数索引，或改存小写
Student.objects.filter(name__iexact="tom")
```

#### 15. `explain()` 分析 SQL

```python
qs = Student.objects.filter(status=1).select_related("class_obj")
print(qs.explain())
```

输出执行计划，看是否走索引、是否有全表扫描。

### 八、综合示例：一个博客系统

```python
from django.db import models


class Author(models.Model):
    name = models.CharField(max_length=50, db_index=True)
    bio = models.TextField(blank=True)


class Category(models.Model):
    name = models.CharField(max_length=50)
    parent = models.ForeignKey(
        "self", on_delete=models.CASCADE,
        null=True, blank=True, related_name="children",
    )


class Tag(models.Model):
    name = models.CharField(max_length=50, unique=True)


class Article(models.Model):
    title = models.CharField(max_length=200, db_index=True)
    content = models.TextField()
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name="articles")
    category = models.ForeignKey(Category, on_delete=models.SET_NULL, null=True, related_name="articles")
    tags = models.ManyToManyField(Tag, related_name="articles", blank=True)
    is_published = models.BooleanField(default=False, db_index=True)
    views = models.IntegerField(default=0)
    created_at = models.DateTimeField(auto_now_add=True, db_index=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        ordering = ["-created_at"]
        indexes = [
            models.Index(fields=["is_published", "-created_at"]),
            models.Index(fields=["author", "is_published"]),
        ]
```

#### 优化后的查询

```python
# 列表页：文章 + 作者 + 分类 + 标签
articles = (
    Article.objects
    .filter(is_published=True)
    .select_related("author", "category")
    .prefetch_related("tags")
    .order_by("-created_at")[:20]
)

# 作者页：作者 + 已发布文章
author = (
    Author.objects
    .prefetch_related(
        Prefetch(
            "articles",
            queryset=Article.objects.filter(is_published=True).only("id", "title", "created_at"),
            to_attr="published_articles",
        )
    )
    .get(pk=1)
)

# 统计：每个分类的文章数
from django.db.models import Count
Category.objects.annotate(
    article_count=Count("articles", filter=Q(articles__is_published=True))
)
```

### 九、速查表

| 关系 | 字段 | SQL | 预加载 |
|---|---|---|---|
| 一对一 | `OneToOneField` | 外键 + UNIQUE | `select_related` |
| 一对多 | `ForeignKey` | 外键 | `select_related`（正向）/ `prefetch_related`（反向） |
| 多对多 | `ManyToManyField` | 中间表 | `prefetch_related` |
| 多对多带字段 | `through` | 自定义中间表 | `prefetch_related` |
| 自关联一对多 | `ForeignKey("self")` | 自引用外键 | `select_related` |
| 自关联多对多 | `ManyToManyField("self")` | 自引用中间表 | `prefetch_related` |
| 虚拟外键 | `IntegerField` | 无约束 | 手动 |
| 通用外键 | `GenericForeignKey` | content_type + object_id | `prefetch_related` |

### 十、总结

| 问题 | 答案 |
|---|---|
| 范式理论核心 | 1NF 原子性、2NF 完全依赖、3NF 无传递依赖 |
| 一对一 | `OneToOneField`，外键 + UNIQUE |
| 一对多 | `ForeignKey`，Django 自动加索引 |
| 多对多 | `ManyToManyField`，自动建中间表 |
| 中间表带字段 | `through` 指定自定义中间模型 |
| 自关联 | `ForeignKey("self")` 或 `ManyToManyField("self")` |
| `symmetrical` | 多对多自关联是否对称，关注用 `False` |
| 虚拟外键 | 只存 ID，不建约束，跨服务用 |
| `GenericForeignKey` | 一个模型关联多种模型 |
| N+1 问题 | 循环里查关联对象，每次一条 SQL |
| 一对一/多对一优化 | `select_related`（JOIN） |
| 多对多/一对多反向优化 | `prefetch_related`（2 次查询） |
| 只读数据 | `values()` / `values_list()` |
| 大数据遍历 | `iterator()` |
| 判断存在 | `exists()` |
| 批量操作 | `bulk_create` / `bulk_update` / `update` |
| 索引 | `db_index=True` 或 `Meta.indexes` |

**核心三句话**：

1. **范式决定表怎么拆**：一对一拆扩展表，一对多多方存外键，多对多建中间表。
2. **N+1 是最大性能杀手**：用 `select_related` 和 `prefetch_related` 预加载。
3. **关系决定优化方式**：一对一/多对一用 `select_related`，多对多/一对多反应用 `prefetch_related`。
