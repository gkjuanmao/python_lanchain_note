```python
agent = create_agent(model=model, tools=[web_search], name="web_search_agent")
```

## 7. Agent的高级用法3：结构化输出

第06章已经介绍过结构化输出，当时的重点是与**模型对象**的绑定，这里与Agent的结构化输出做对比：

| 维度       | 模型的结构化输出                  | Agent 结构化输出                 |
| :------- | :------------------------ | :-------------------------- |
| **操作对象** | 作用于大模型对象                  | 作用于 Agent                   |
| **解析时机** | 每次模型调用生成 AIMessage 时，进行解析 | 仅在 Agent 决定"任务结束"并输出最终答案时解析 |
| **数据流转** | 模型 → 结构化对象                | 模型 → 工具 → 反思 → ... → 结构化对象  |
| **绑定方式** | 使用 with_structured_output | 使用 response_format 参数       |
| **适用场景** | 单次、确定性的任务（如提取字段、翻译、分类）    | 多步、复杂推理的任务（如查文档后汇总报表）       |
### 结构化输出的四种策略

#### ① ProviderStrategy  

```python
from langchain.agents.structured_output import ProviderStrategy
from pydantic import BaseModel, Field


class Person(BaseModel):
    """人物信息"""
    name : str = Field(description="姓名")
    age :int = Field(description="年龄")
    sex :str = Field(description="性别")
    email :str = Field(description="邮箱")


agent = create_agent(model=model, response_format=ProviderStrategy(Person))

response = agent.invoke(
    {
        "messages": [
            HumanMessage(content="张三 30岁，男，zhangsan@example.com，使用json格式返回"),
        ]
    }
)

rprint(response)


```

### 错误处理：handle_errors 参数

受限于模型能力，大模型输出的内容可能并不符合格式要求，`ToolStrategy`通过其 `handle_errors`参数提供了结构化过程错误处理策略，以下是主要的几种方式及其用途：
- **handle_errors=True**：`LangChain`默认方式，捕获所有异常，并使用`LangChain`内置的、信息明确的错误消息模板提示模型重试，确保最终能得到符合预定格式的有效数据。适用于大多数希望自动处理错误的通用场景。
- **handle_errors=False**：关闭自动重试机制，任何异常都会直接抛出，会中断程序运行。
- **handle_errors="自定义字符串"**：捕获所有异常，但使用开发者预设的固定字符串作为错误消息。适用于需要统一、友好的用户提示，或进行特定业务引导的场景。
- **handle_errors=ExceptionType**：仅捕获指定类型(如`ValueError`)或元组中的异常类型并进行重试，其他异常直接抛出。适用于需要精准控制，只对特定错误进行重试的场景。
- **handle_errors=callable**：灵活性最高的方式，使用开发者自定义的函数来处理异常，可根据不同的异常类型返回差异化的提示信息。适用于需要复杂、精细化错误处理的场景。

```python
import os
from typing import Annotated, TypedDict, Union

from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy
from langchain_core.messages import HumanMessage
from langchain_deepseek import ChatDeepSeek
from pydantic import ValidationError
from rich import print as rprint


# ==========================================
# 1. 定义触发错误的数据结构
# ==========================================
# 注意：这里我们要求手机号长度必须为 100，强行让模型提取的 11 位手机号校验失败
class ContactInfo(TypedDict):
    """联系信息"""

    name: Annotated[str, "姓名"]
    phone: Annotated[str, "手机号"]
    email: Annotated[str, "邮箱"]


class EventDetails(TypedDict):
    """事件详情"""

    event_name: Annotated[str, "事件名称"]
    event_date: Annotated[str, "事件日期"]


# 初始化模型 (建议使用 deepseek-chat，因为 reasoner 不支持强制的 tool_choice)
model = ChatDeepSeek(model="deepseek-chat", temperature=0)

prompt = {
    "messages": [
        HumanMessage(
            content="提取信息：张三 13800000000 zhangsan@example.com，活动名称：公司年会，活动日期：2024-01-01"
        )
    ]
}

print("================ 演示开始 ================\n")

# ==========================================
# 演示 1: handle_errors=True (默认)
# ==========================================
print("--- 1. handle_errors=True ---")
agent_1 = create_agent(
    model=model,
    response_format=ToolStrategy(
        schema=ContactInfo | EventDetails,
        tool_message_content="格式化成功",
        handle_errors=True,  # 默认捕获所有异常，自动重试
    ),
)

response = agent_1.invoke(prompt)
rprint(response["structured_response"])

```

```python
# 演示 2: handle_errors=False
# ==========================================
print("\n--- 2. handle_errors=False ---")
agent_2 = create_agent(
    model=model,
    response_format=ToolStrategy(
        schema=ContactInfo | EventDetails,
        tool_message_content="格式化成功",
        handle_errors=False,  # 直接抛出异常，不重试
    ),
)

response = agent_2.invoke(prompt)
rprint(response)

```

```python

# 演示 3: 自定义字符串
# ==========================================
```

```python
# ==========================================
# 演示 5: 指定错误处理函数
# ==========================================
from langchain.agents.structured_output import (
    MultipleStructuredOutputsError,
    StructuredOutputValidationError,
)


def custom_error_handler(error: Exception) -> str:
    rprint(f"捕获到的错误信息是:{type(error).__name__}")
    rprint(f"错误信息详情:{error}")
    if isinstance(error, MultipleStructuredOutputsError):
        return "检测到多个响应，请选择联系信息进行返回"
    elif isinstance(error, StructuredOutputValidationError):
        return "数据格式有误，请检查字段是否符号要求。"
    else:
        return f"发生错误: {error}"


print("\n--- 5. 指定错误处理函数 ---")
agent_5 = create_agent(
    name="agent_5",
    model=model,
    response_format=ToolStrategy(
        schema=ContactInfo | EventDetails,
        tool_message_content="格式化成功",
        handle_errors=custom_error_handler,  # 直接抛出异常，不重试
    ),
)

response = agent_5.invoke(prompt)
rprint(response["structured_response"])
```

## 8. Agent的高级用法4：流式输出

通过`agent.stream(stream_mode=指定模式)`来指定，具体模式有：values,updates(默认),messages,custom,checkpoints,tasks,debug

### 7 种流模式对比

| 模式 (`stream_mode`) | 流式输出内容                                                                                                                                                                                                                    | 典型用途                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| **`values`**       | 每一步执行后，图的**完整状态**快照[](https://docs.langchain.com/oss/python/langgraph/streaming.md)[](https://docs.langchain.com/langsmith/streaming)[](https://mintlify.wiki/langchain-ai/langgraph/concepts/streaming)                  | 调试、回放、监控完整状态变化      |
| **`updates`**      | 每一步执行后，仅返回该节点产生的**状态更新**（增量）[](https://docs.langchain.com/oss/python/langgraph/streaming.md)[](https://docs.langchain.com/langsmith/streaming)[](https://mintlify.wiki/langchain-ai/langgraph/concepts/streaming)         | 进度条、状态侧边栏、查看哪个节点在运行 |
| **`messages`**     | 大模型生成的**逐 Token 文本流**（包含元数据）[](https://docs.langchain.com/oss/python/langgraph/streaming)[](https://docs.langchain.com/oss/python/langgraph/streaming.md)[](https://docs.langchain.com/oss/python/langchain/streaming.md) | 聊天界面、实时打字机效果        |
| **`custom`**       | 从节点或工具内部发出的**自定义数据**[](https://docs.langchain.com/oss/python/langgraph/streaming)[](https://mintlify.wiki/langchain-ai/langgraph/concepts/streaming)[](https://docs.langchain.com/oss/python/langchain/streaming.md)      | 精细化的进度追踪、自定义指标上报    |
| **`debug`**        | 包含检查点（checkpoints）和任务（tasks）的**详尽调试信息**[](https://docs.langchain.com/langsmith/streaming)[](https://mintlify.wiki/langchain-ai/langgraph/concepts/streaming)                                                              | 开发阶段的故障排查、性能分析      |
| **`tasks`**        | 任务的**生命周期事件**（开始、结束、结果）[](https://mintlify.wiki/langchain-ai/langgraph/concepts/streaming)                                                                                                                                | 监控任务执行时长、追踪失败原因     |
| **`checkpoints`**  | 创建检查点时的**状态快照**[](https://mintlify.wiki/langchain-ai/langgraph/concepts/streaming)                                                                                                                                        | 监控状态持久化过程、显示执行时间线   |
